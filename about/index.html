HOW IT'S MADE

AI との分担

  1. 1

    人が仕様を決める

    仕様の抜けは AI が論点にして出し、人が選んで確定させます。

  2. 2

    研究

    いいねの確率のモデルは人が作りました（次の章）。

  3. 3

    Claude Code が作る

    仕様をもとに画面とロジックを書き、テストを付けます。

  4. 4

    Codex が見直す

    仕様との違いや計算の誤りを挙げます。どれを直し、何を取り込むかは人が決めます。

見直しの回数には上限があり、残った指摘は人が判断します。Codex はコードを触りません。相手のアイコンなどの画像は主に Codex の画像生成で作って加工し、使うものを人が選んでいます。

MODEL

いいねの確率のモデル

いいねする確率と返す確率は、人が式を立てました。シミュレーションを回すと、前提に入れていない傾向が出てきて、どれも先行研究で知られている傾向と合いました。

  • 人気のある相手に集まる

    いいねの7〜8割が、自分より人気のある相手へ。

  • 大きく上だと返りにくい

    男性から女性へは、差が小さいと約27%返ってくるのが、大きく上だと約2%まで下がります。

  • マッチした2人は似る

    マッチした2人の魅力の相関は0.40（魅力を1つにまとめたモデル）。

NOT BUILT

作らなかったもの

  • ランキングと、セーブのサーバー保存

    どちらもサーバーが要ります。結果は、共有の文と画像で外に出せます。

  • 会話を自分で打つ操作

    やりとりの会話は、文例から自動で出します。選べるのは、デートの行き先とそこですること、ときどき届く一言への返し方など。遊びの中心は、限られたいいねをだれに送るかです。

  • LLM を使う案

    LLM に答えを付けさせて学習する案は、手作業が重く、答えが正しいとも限らないのでやめました。ゲームから LLM の API を呼ぶ案も見送りました。

TESTS

同じシードで同じ結果に

ゲームの乱数は、シードという1つの数から作っています。シードが同じなら乱数の並びも同じなので、遊び方が同じなら結果も同じになります。これを使って、直しで遊びの中身が変わっていないかを確かめます。

  1. 同じシード
  2. 決めた遊び方で何十日か進める
  3. 状態のスナップショットを取る
  4. 前のスナップショットと同じか

ロジックは画面から切り離してあるので、画面を開かずに何十日分でも進められます。スナップショットを取り直すのは遊び方や数値を変えたときだけで、理由をテストに残します。AI に処理を速くさせるときも、スナップショットが変わらないことを条件にしました。

IN YOUR BROWSER

計算はブラウザの中で

確率は、研究の式を JavaScript にした小さな関数で、その場で計算します。セーブもブラウザの中に残ります。外に送るのは、ゲームが終わったときのそのゲームの記録（結果の数字と、ゲームの中の自分や相手のプロフなど）で、設定で止められます（送る項目はプライバシー）。
